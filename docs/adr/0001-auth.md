# ADR 0001: 認証は自前 Argon2id + DB セッション

- 日付: 2026-10-21
- 状態: 採用

## 背景

M1 ではチーム共有（admin / operator / viewer）を前提に、メール + パスワードのログイン、セッション、ロール判定、監査ログ、ログイン試行制限が必要になった。

PLAN では better-auth を第一候補、Argon2id + 自前セッションを代替としていた。既存の ER では `users` / `sessions` を独自スキーマで定義しており、`audit_logs` や `port_reservations` からユーザー ID を参照する。

## 決定

**自前の Argon2id パスワードハッシュ + DB セッション**を採用する。

- パスワード: `hash-wasm` の Argon2id
  - `parallelism=1`, `iterations=2`, `memorySize=19456` KiB（19 MiB）, `hashLength=32`
  - ソルトは 16 バイトの乱数。エンコード形式（`$argon2id$...`）で保存
- セッション
  - 32 バイトの乱数トークンを `base64url` でクライアントに渡す
  - DB には SHA-256 ハッシュのみ保存（`sessions.token_hash`）
  - Cookie 名 `sys4sys_session`、HttpOnly / SameSite=Lax / `COOKIE_SECURE` で Secure
  - 既定 TTL 168 時間（`SESSION_TTL_HOURS`）
- ロール: `users.role` の `admin` / `operator` / `viewer` を `requireRole()` で判定
- ログイン試行制限: メモリ内の固定ウィンドウ（既定 5 回 / 15 分、IP + メール単位）
- 監査: ログイン成功・失敗、ログアウト、パスワード変更を `audit_logs` に記録
- 初期管理者: `users` が空のとき `ADMIN_EMAIL` / `ADMIN_PASSWORD` から作成。開発時にパスワード未設定ならランダム生成して起動ログに表示

## 理由

- 既存の `users` / `sessions` スキーマをそのまま使え、ER の変更が不要
- ロール、監査ログ、レート制限、初期管理者作成をアプリの都合に合わせて実装できる
- better-auth の user/session/account/verification テーブルとアダプタ設定を既存 ER に合わせるコストを避けられる
- `hash-wasm` は WASM 実装で、Windows でのネイティブビルドを必要としない

## 代替案

- **better-auth**: 機能は豊富だが、スキーマ統合と設定が増える。M1 の要件（3 ロール、監査、既存 ER）には過剰と判断
- **Node.js `crypto.scrypt`**: 依存なしだが、PLAN の Argon2id 方針に合わせて却下
- **`@node-rs/argon2`**: 高速だがプラットフォーム別のネイティブバイナリに依存するため、WASM を優先

## 運用上の注意

- 本番では `ADMIN_PASSWORD` を必ず設定し、初回ログイン後にパスワードを変更する
- レート制限は単一プロセス前提のメモリ内実装。複数インスタンスに横展開する場合は Redis などに移す
- セッショントークンは DB に平文保存しない（SHA-256 のみ）
- HTTPS 運用時は `COOKIE_SECURE=true` にする
